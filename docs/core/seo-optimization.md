# SEO Optimization

## Meta tags & structured data

Handled centrally in `src/components/layout/BaseHead.astro`:

- Title tags & meta descriptions (unique per page, passed as props)
- Open Graph & Twitter Cards
- `WebApplication` JSON-LD structured data (name/description driven by props,
  optional `featureList`)
- Canonical URLs
- GA4 analytics scaffold (see below)

## Sitemap

Auto-generated by `@astrojs/sitemap`, configured in `astro.config.mjs`. The
template ships a simple 2-tier `serialize()`:

- Homepage: 1.0, daily
- Everything else: 0.5, monthly

Adjust the tiers in `astro.config.mjs` as your page taxonomy grows.

## Domain configuration

Set in `src/config/site.ts` (read by `astro.config.mjs` for the Astro `site`
setting):

```typescript
export const site = {
  name: "My Web Tool",
  url: "https://my-tool.bobadilla.tech",
  // ...
};
```

`public/robots.txt` uses a relative `Sitemap: /sitemap-index.xml` path, so it
requires no edits when you change the domain.

## Content strategy

Add new pages under `src/pages/`, and link them from `Header.astro` /
`Footer.astro` so they're actually crawlable, not just present in the
sitemap. Keep content genuinely useful rather than thin or templated —
near-duplicate pages are a doorway-page pattern search engines penalize.

Backlinks to `site.brand.url` / `site.related.*` (Bobadilla Tech, Requiems
API, Lorelai) are pre-wired in the Footer if you want to keep that
cross-promotion; drop them from `Footer.astro` if a given project shouldn't
carry it.

## After deployment

1. **Google Search Console** — verify domain, submit `sitemap-index.xml`.
2. **Bing Webmaster Tools** — same.
3. Confirm OG image renders in link previews (WhatsApp/Twitter/LinkedIn) after
   any change to `public/images/og-image.png` — social platforms don't render
   SVG previews, so it must stay a PNG at 1200×630.
